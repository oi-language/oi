# Oi 0.0.2 Language and Toolchain Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 交付不可变的 Oi `0.0.2` 语言快照，以 deterministic collections、受限 judgment、aggregate derivation、显式 source manifest、sealed execution context 和 typed execution receipt 支撑大型 Oi Skill，并通过插件包装版本 `0.0.3` 安装。

**Architecture:** 保留 Agent 直接解释 `.oi` 的执行模型；`execution.md` 继续作为单一基础语言规范，按需 runtime shards 只展开其动态语义。先用新的 versioned corpus 固化失败与成功观察，再让现有 0.0.1 compiler 作为 bootstrap compiler 支持 0.0.2，随后把 bundled tools 自身迁移到 0.0.2。语言快照、stdlib、adapters、examples、corpus 和工具链一起形成语言发布单元；六个 host manifest 只负责独立的包装版本。

**Tech Stack:** Oi 0.0.1 bootstrap、Oi 0.0.2、Markdown language/runtime specifications、JSON plugin manifests、PowerShell read-only verification、Git。

**Design Source:** `docs/superpowers/specs/2026-08-16-oi-0.0.2-language-design.md`

## Global Constraints

- 不修改 `plugins/oi/skills/using-oi/versions/0.0.1/`；每个里程碑和最终发布均用 Git 对比已发布 tag `0.0.1`。
- Oi 保持 0% scripts、100% Skill：不新增 Python、JavaScript、TypeScript、Shell、PowerShell、batch、binary、生成 capsule、VM 或第二 runtime。
- `.oi` 承担产品行为；`SKILL.md` 只触发、加载、路由、声明入口与 host mapping。
- `using-oi/versions/0.0.2/execution.md` 是唯一 base-language 文件；runtime shards 不重新定义 grammar 或 static semantics。
- 所有 0.0.2 executable modules 都有 nearest `oi.mod`、精确 `oi 0.0.2` 和排序后的 `source` manifest；不再依赖目录发现。
- 每个 product `.oi` 文件不超过 16,000 decoded characters，每行不超过 240 characters；reachable project graph 不超过 128,000 decoded characters。
- `execution.md` 不超过 14,000 characters；compact prefix 不超过 2,500；prefix 加 adapter 不超过 4,000；adapter 不超过 1,500；每个 runtime shard 不超过 5,000。
- collection 使用 value semantics 和 canonical iteration；normal judgment 不返回 unbounded aggregate；`derive` 不访问 ambient context、effects 或 control。
- 0.0.2 entry admission 必须 sealed；每次 entry attempt 都产生 receipt，started-without-completion 的 effect 标记为 indeterminate。
- receipt 是 deterministic audit evidence，不声称抵抗恶意 host；敏感 canonical values 只进入 protected journal，receipt 只保存 type/digest/identity。
- 不修改 `E:\Projects\subpowers` 或任何外部 runtime。三个真实会话只通过仓库内 distilled cases 形成验收证据。
- 行为变更先添加或更新 corpus，再实现；先跑最小验证，再跑 cross-tool 和 release gates。
- 每项提交只包含本任务列出的文件；提交格式使用 `[action] 中文说明。`。

## Canonical Public Interfaces

Implement these interfaces once and reuse them; do not create parallel text protocols.

```oi
// versions/0.0.2/std/execution/execution.oi
package execution

type ArtifactIdentity struct {
    Path text
    Bytes int
    Characters int
    SHA256 text
}

type ValueIdentity struct {
    Type text
    Digest text
}

type TypedValue struct {
    Type text
    Canonical text
    Digest text
}

type MappingIdentity struct {
    Effect text
    Signature text
    Authorities []text
    HostMapping text
    Digest text
}

type OperationKind enum {
    Allocation
    Judgment
    Derivation
    Iteration
    Effect
    TaskLaunch
    TaskCompletion
    Await
    Join
    Detach
    DetachNotification
    TaskStatus
    TaskCancel
    ChannelCreate
    MessageCommit
    Send
    Receive
    Select
    UserSuspension
    Handoff
    Reply
}

type OperationStatus enum {
    Started
    Completed
    Failed
    Indeterminate
    Cancelled
}

type TerminalStatus enum {
    Completed
    Failed
    Stopped
}

type Operation struct {
    ID text
    Kind OperationKind
    Location text
    Status OperationStatus
    Inputs []ValueIdentity
    Output ValueIdentity?
    Failure diagnostic.Diagnostic?
}

type ExecutionReceipt struct {
    LanguageVersion text
    Module text
    Entry text
    Manifest []text
    Artifacts []ArtifactIdentity
    Inputs []ValueIdentity
    Mappings []MappingIdentity
    Authorities []text
    AuthoritiesIdentity ValueIdentity
    Policy ValueIdentity?
    Operations []Operation
    ReplyOperationID text?
    Reply ValueIdentity?
    Terminal TerminalStatus
    Failure diagnostic.Diagnostic?
    LoadedCharacters int
    ProjectCharacters int
}

type JournalEntry struct {
    Operation Operation
    Inputs []TypedValue
    Output TypedValue?
}

type ExecutionJournal struct {
    Policy TypedValue?
    Entries []JournalEntry
}
```

Direct canonical operation IDs never cross kinds. An allocated `oN` first has one `Allocation.Completed` record, then one fixed boundary kind. `TaskLaunch`, `ChannelCreate`, `MessageCommit`, and `Select` create their canonical IDs atomically; `TaskCompletion` and `DetachNotification` are separate owner/registry `oN` boundaries with Allocation, Started, and one terminal state, carrying TaskID only in typed input/result. Other non-atomic boundaries use the same `oN` transition shape, and interleaved operations do not require equal-ID adjacency.

Receipt terminal framing uses only the public `Completed | Failed | Stopped` enum. `Completed` has no Failure. A causal root-ending `Failed`, `Indeterminate`, or `Cancelled` operation projects `Failed` with the exact Failure. `Stopped` carries the exact controller Failure and is reserved for explicit post-admission controller termination without a program semantic failure or causal terminal operation; direct program execution never emits it.

Named contracts run on first construction/conversion/input binding, on underlying or unvalidated to named conversion, and when the target named type changes. An immutable already-validated exact same named type/value reuses its validation evidence across assignment, argument, return, and effect boundaries without a new Judgment.

The compiler report gains source identity without exposing source bodies:

```oi
type SourceIdentity struct {
    Path fs.Path
    Bytes int
    Characters int
    SHA256 text
}

type CompileReport struct {
    Status Status
    LanguageVersion text?
    Module text?
    SourceCount int
    SourceCharacters int
    Sources []SourceIdentity
    Authorities []text
    Shards []text
    Diagnostics []diagnostic.Diagnostic
}
```

Suite `CompileObservation` preserves this canonical report identity. The host copies language, module, counts, and ordered source identities verbatim from the direct loader/compiler report for that observation's exact `CaseID+Target`; they are the trusted independent compile boundary, never values inferred from the runtime caller. Before any receipt, journal, artifact, or digest validation, the matching runtime observation cross-binds its structured target evidence to that same compile observation: compiler version `0.0.2` maps only to snapshot identity `Oi 0.0.2`, while module, counts, and each ordered source field match exactly. Caller-supplied runtime hashes are not independent evidence by themselves.

The debugger entry becomes typed and receipt-aware:

```oi
func main(
    target fs.Path,
    bindings []debug.Binding,
    journal execution.ExecutionJournal,
    receipt execution.ExecutionReceipt,
    transcript []debug.EffectResult,
)
```

`debug.Binding.Value` and `debug.EffectResult.Value` use `execution.TypedValue`; `DebugTrace` adds `ReceiptValid bool` and `ReceiptDiagnostics []diagnostic.Diagnostic`.

The converter entry makes the target snapshot explicit:

```oi
func main(
    source fs.Path,
    destination fs.Path,
    module text,
    targetVersion text,
    mode convert.Mode,
    proof text?,
)
```

The benchmark execution host mapping keeps its call shape. `report.TestReport` is exactly `Status, Observations, ForbiddenHits, Failure, LanguageVersion text, Receipt execution.ExecutionReceipt?, ReplyDigest text?`; the trusted host fills LanguageVersion from the target's nearest exact `oi.mod`, never caller or observation text. `bench.Case` adds `Mode CaseMode` between `ID` and `Target`, where `CaseMode` is exactly `Compilation | Execution`. Compilation calls only a separate typed `CompileTarget(target fs.Path, input text, observe text, forbid text) report.TestReport` effect mapped to `tool.compile`; it compiles in a fresh sealed compile context, never invokes the target entry/effects, and returns absent Receipt/ReplyDigest. Execution calls only the unchanged `InvokeTarget(...)` mapping and trusts provenance from that current activation's `agent.invoke` completion: the host mapping creates the fresh sealed target context, binds the requested target/input to the resolved source, mapping, authority, and policy identity, and returns the actual receipt and Reply digest. Each case first requires actual LanguageVersion equal to `RunIdentity.LanguageVersion`; only an actual `0.0.1` completion may take the legacy receipt-free path, while actual `0.0.2` requires receipt evidence. Mode is never encoded into observation text or fixture names, and one effect is never reused before discarding evidence. The benchmark rechecks the public receipt fields. `ExecutionReceipt` remains an ordinary public value with no seal token, and a malicious host that substitutes a field-for-field identical receipt is outside the 0.0.2 threat model. `ExecutionReceipt.Entry` plus the trusted effect completion is the entry-boundary proof because the canonical `OperationKind` intentionally has no Entry member. A trusted-host identity rejection is exactly `BENCH_EVIDENCE_MISMATCH|runtime|target:1:1|sealed invocation mismatch: <FieldPath>|[]`; the first field follows Target, LanguageVersion, artifact manifest/source order, Inputs, Mappings, Authorities, AuthoritiesIdentity, Policy, Entry, Terminal, ReplyOperationID, then Reply.Digest.
